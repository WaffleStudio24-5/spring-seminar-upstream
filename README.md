# Spring Seminar 과제 안내

와플스튜디오 Spring 세미나의 공통 과제 스켈레톤 저장소입니다. 매주 운영진이 제공하는 변경사항을 받아, 기존 구현에 새로운 기능을 추가하며 애플리케이션을 발전시킵니다.

이 README는 시작하기, 업데이트, 제출, 결과 확인 방법을 안내합니다. **주차별 구현 요구사항, API 명세, 마감일은 해당 주차의 과제 안내를 확인하세요.**

## 주요 링크

- [세미나 자료 및 주차별 과제 안내](https://app.notion.com/p/011b00e8cec4825a997a81b5a8f1087a)
- [채점 결과 확인 — 리더보드](https://spring-seminar-judge.vercel.app/)
- [원본 스켈레톤 저장소](https://github.com/WaffleStudio24-5/spring-seminar-upstream)

## 시작하기

1. 이 저장소를 본인 또는 팀 계정으로 **Fork**합니다. 개인·팀 진행 여부는 주차별 안내를 따릅니다.
2. Fork한 저장소를 로컬에 clone합니다. 아래 `<계정>`은 본인 또는 팀의 GitHub 계정으로 바꿉니다.

   ```bash
   git clone https://github.com/<계정>/spring-seminar-upstream.git
   cd spring-seminar-upstream
   ```

3. IDE에서 프로젝트 루트 폴더를 열고 Gradle 프로젝트를 불러옵니다.
4. 현재 프로젝트에 필요한 **JDK 21**을 설치하고 IDE의 Gradle JVM도 맞춥니다. 이후 환경 변경은 운영진 안내와 `build.gradle.kts`를 확인합니다.
5. Fork 저장소의 **Actions** 탭에서 워크플로가 비활성화되어 있다면 활성화합니다.

Gradle은 저장소에 포함된 Wrapper를 사용하므로 별도로 설치할 필요가 없습니다. 자동 채점을 위한 GitHub Actions variable이나 secret 설정도 필요하지 않습니다.

## 실행과 로컬 테스트

프로젝트 루트에서 실행합니다.

```bash
# 애플리케이션 실행
./gradlew bootRun

# 테스트 실행
./gradlew test
```

현재 기본 서버 주소는 `http://localhost:8080`입니다. Windows PowerShell에서는 각각 `./gradlew.bat bootRun`, `./gradlew.bat test`를 사용합니다.

미구현 기능에 대한 테스트는 실패할 수 있습니다. 실패한 테스트의 요청과 기대 응답을 읽고, 주차별 과제 안내와 함께 구현할 동작을 확인하세요. 로컬 테스트 보고서는 `build/reports/tests/test/index.html`에서 볼 수 있습니다.

DB 등 별도의 실행 환경이 필요한 주차에는 해당 주차의 준비 안내도 따릅니다.

## 매주 원본 변경사항 받기

처음 한 번, 원본 저장소를 `upstream`으로 등록합니다. `origin`은 본인 또는 팀의 Fork 저장소로 유지합니다.

```bash
git remote add upstream https://github.com/WaffleStudio24-5/spring-seminar-upstream.git
git remote -v
```

이미 `upstream`이 등록되어 있다면 주소만 확인하면 됩니다. 운영진이 업데이트를 공지하면 진행 중인 작업을 커밋해 보관한 뒤 다음 명령을 실행합니다.

```bash
git switch main
git pull --ff-only origin main
git fetch upstream
git merge upstream/main
```

충돌이 발생하면 기존 구현과 새 스켈레톤의 변경 의도를 함께 확인해 해결하고 merge를 완료합니다. 업데이트 후에는 변경된 과제 안내와 테스트를 읽고 `./gradlew test`를 실행하세요.

**현재 자동 채점은 실행 시점의 원본 `main`을 기준으로 합니다.** 오래된 로컬 스켈레톤으로 테스트하면 채점 환경과 결과가 다를 수 있으므로, 제출 전에 공지된 업데이트를 반영하세요.

## 구현 범위와 채점 기준

API 계약과 공개 테스트가 기대하는 동작을 만족하도록 구현합니다. 내부 구조는 주차별로 명시된 제약 안에서 자유롭게 설계할 수 있습니다.

| 경로 | 역할과 채점 반영 여부 |
| --- | --- |
| `src/main` | 구현 코드와 리소스입니다. **이 디렉터리 전체가 채점에 반영됩니다.** |
| `src/test` | 공개 테스트가 있습니다. 자체 테스트를 추가할 수 있지만, 채점에는 운영진 원본 테스트를 사용합니다. |
| `build.gradle.kts`, `settings.gradle.kts`, Gradle Wrapper | 운영진이 관리하는 빌드 환경입니다. Fork에서 변경해도 채점 환경에는 반영되지 않습니다. |
| `.github/workflows/grade.yml` | 자동 채점을 실행하는 설정입니다. 운영진 안내 없이 변경하지 마세요. |

채점은 **운영진 원본의 빌드 설정·테스트에 제출한 `src/main`을 결합**해 실행합니다. 테스트를 삭제하거나 기대값을 수정해도 채점 기준은 바뀌지 않습니다. 의존성을 임의로 추가하면 로컬에서 성공해도 채점에서는 빌드가 실패할 수 있으니, 필요한 경우 운영진에게 먼저 문의하세요.

## 제출 방법

1. 공지된 원본 업데이트를 반영합니다.
2. 구현을 완료하고 로컬 테스트 결과를 확인합니다.
3. 제출할 변경사항을 커밋하고 **Fork 저장소의 `main`에 push**합니다.

   ```bash
   git push origin main
   ```

현재 워크플로는 `main`에 push할 때 자동 채점합니다. 다른 브랜치에 push하거나 PR을 생성하는 것만으로는 채점되지 않습니다. PR로 작업했다면 리뷰 후 `main`에 merge해야 합니다.

제출 대상은 본인 또는 팀의 Fork 저장소입니다. 원본 저장소로 PR을 보내는 방식이 아닙니다. 마감과 최종 제출 인정 기준은 주차별 안내를 따릅니다.

## 채점 결과 확인

1. Fork 저장소의 **Actions → Grade**에서 제출 커밋에 해당하는 실행을 확인합니다.
2. 실패했다면 실행 상세에서 빌드·테스트 로그를 확인합니다.
3. [리더보드](https://spring-seminar-judge.vercel.app/)에서 저장소, 과제, 상태, 채점 시각, 실행 번호를 확인합니다. 필요하면 새로고침합니다.

리더보드는 채점 결과를 확인하는 화면이며, 실패 원인은 Actions 로그에서 확인합니다. 표시된 실행 번호가 방금 제출한 실행과 일치하는지도 확인하세요.

| 상태 | 의미 |
| --- | --- |
| `PASSED` | 채점 작업이 성공했습니다. |
| `FAILED` | 채점 작업이 실패했습니다. 테스트 실패뿐 아니라 빌드·환경 오류일 수도 있으므로 로그를 확인하세요. |
| `ERROR` | 취소 등으로 채점 작업이 정상적인 성공·실패 결과를 내지 못했습니다. 실행 상세를 확인하세요. |

채점 작업과 결과 전송은 별도 단계입니다. 테스트가 통과했어도 리더보드에 결과가 없다면 Actions의 결과 전송 작업(`report`)도 확인하세요.

## 문제가 생겼을 때

- **채점이 시작되지 않음:** Fork의 Actions 활성화 여부, push한 브랜치가 `main`인지, 채점 워크플로가 유지되어 있는지 확인합니다.
- **로컬에서는 성공하지만 채점은 실패:** 원본 업데이트 누락, JDK 차이, 채점에 반영되지 않는 의존성·테스트 변경, 커밋하지 않은 파일이 있는지 확인합니다.
- **리더보드에 결과가 없거나 이전 결과가 보임:** 실행 완료 여부와 결과 전송 로그를 확인하고 리더보드를 새로고침합니다.

해결되지 않으면 세미나에서 안내한 질문 채널에 다음 정보를 함께 남겨 주세요.

- 주차와 기대한 동작, 실제 발생한 동작
- Fork 저장소 링크와 제출 커밋 SHA
- 실패한 GitHub Actions 실행 링크 또는 로컬 실행 명령
- 오류 메시지와 재현 방법

비밀번호, 토큰, 개인 인증정보는 저장소나 질문에 포함하지 마세요.
